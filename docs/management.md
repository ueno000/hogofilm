# 工程管理（マネージャー）運用手順

仕様シートの変更を GitHub の Issue と Project「development」に反映するための手順。マネージャー役のセッションがこの手順で動く。開発セッションが守るルールは [CLAUDE.md](../CLAUDE.md) にある。

## 管理する場所

| 場所 | 役割 | 正とする情報 |
|---|---|---|
| 企画管理シート（Google スプレッドシート「保護フィルム貼りゲーム 企画管理シート」） | 仕様の数値・パラメータ・配点・称号 | **何を作るか（数値）** |
| [docs/game-plan.md](game-plan.md) | ゲームのルール・流れ・受け入れ条件 | **何を作るか（ルール・文言）** |
| GitHub Issue（`ueno000/hogofilm`） | 作業の単位。仕様変更の履歴はコメントで残す | **作業内容と経緯** |
| GitHub Project「development」（https://github.com/users/ueno000/projects/1） | Status（Todo / In Progress / Done）と Track（Spec / Tech / Release） | **進捗** |

シートのタブの扱い:

| タブ | 種類 | マネージャーの扱い |
|---|---|---|
| 工程設計 / 調整パラメータ / 称号 | 仕様 | 読むだけ。**編集しない** |
| 進捗 | 管理 | Project の写しとして同期する（編集してよい） |
| パラメータCSV | 出力 | 調整パラメータから数式で値を引く、CSV 出力専用のタブ。名前（A列）の行を足し引きしてよい |
| プレイテスト記録 | 記録 | 読むだけ。気づいたことを Issue の材料にする |

## マネージャーの権限

- **してよい**: Issue の起票・コメント・ラベル付け、Project の Status / Track の更新、シートの管理部分（進捗タブ、パラメータCSV タブ、Issue 番号欄）の編集、管理ドキュメント（`CLAUDE.md`、`docs/management.md`）の更新、コードの参照
- **しない**: `src/`・`tests/`・設定ファイルなど動くものの変更、シートの仕様部分の編集、開発セッションの作業ツリーやブランチの操作
- 管理ドキュメントの変更は、別の worktree で `docs/` ブランチを切り、`develop` 向けに PR を出す。マージはユーザーが判断する。

## 仕様変更が来たときの手順

ユーザーから「仕様が変わった」と連絡を受けたら、次の順に進める。

1. **シートを読む** — 仕様タブ（工程設計・調整パラメータ・称号）と、プレイテスト記録の新しい行を読む。
2. **コードと突き合わせる** — 調整パラメータの「現在値」と、コード中の同名の定数を比べる（ファイルは「ファイル」列に書いてある）。工程設計の配点は `src/game/score.ts` の `STAGE_WEIGHTS` と比べ、完了条件・品質・失敗時の扱いは各工程のロジックと比べる。
3. **ずれを Issue にする**
   - 既存の Issue の範囲内なら、その Issue にコメントで追記する（本文は書き換えない）。
   - 新しい作業になるなら、Issue を起票し、Project に追加する（Track=Spec、Status=Todo）。
   - 完了済みの Issue に関わる変更は、新しい Issue を起票し、元の Issue を `#番号` で参照する。
4. **Project を更新する** — Status と Track が正しいか確認する。
5. **進捗タブを同期する** — Project の Status をシートの進捗タブに写す（Todo=未着手、In Progress=進行中、Done=完了）。
6. **ユーザーに報告する** — 起票・コメントした Issue と、シート側で気になった点（入力ミスなど、仕様タブにある問題は直さずに報告する）。

### Issue コメントの書式

```markdown
## 仕様変更（シート: <タブ名> / <項目>）

- **変更内容**: <変更前> → <変更後>
- **理由**: <シートの変更メモ・プレイテスト結果・ユーザーの指示など>
- **影響範囲**: <関係するファイル・定数・工程・他の Issue>
```

## 調整値の CSV（パラメータCSV タブ）

ゲームの調整値は `src/params.csv` から読み込む（#35）。企画はこの CSV を差し替えて値を試せる。

**企画が値を変えるとき**
1. 調整パラメータタブの「現在値」を書き換える
2. パラメータCSV タブを開き、ファイル → ダウンロード → カンマ区切り形式（.csv、現在のシート）でダウンロードする
3. ダウンロードしたファイルで `src/params.csv` を上書きする（ファイル名は `params.csv` にする）
4. `npm run dev` 中ならそのまま反映される。公開版はビルドし直して反映する

**タブのしくみ**
- 1行目は見出し（`name,value,unit,stage,description`）、2行目以降はデータだけ。CSV に混ざるので、タイトルや注記は置かない
- A列（name）は定数名を手で並べる。B〜E列は、調整パラメータタブから同じ定数名の行を `XLOOKUP` で下から探して引く。同じ名前が2行あるとき（実装済みと提案中の両方にあるなど）は、下の行（新しいほう）の値になる。調整パラメータに名前がないと、value 列が「未登録」になる（そのまま CSV にするとゲームが起動時にエラーを出す）
- 並べるのはコードで実装済みの定数だけ。提案中の値は載せない

**マネージャーがすること**
- 新しい定数が実装されたら、A列に名前を足し、1つ上の行の B〜E列の数式をコピーする。実装で使わなくなった定数は行を消す
- 仕様変更の手順の 2（コードと突き合わせる）では、パラメータCSV タブの値と `src/params.csv` も比べる。ずれていたらユーザーに知らせる（CSV の差し替えは企画が行う）

## 称号の CSV（称号CSV タブ）

称号の言葉とひとことは `src/titles.csv` から読み込む（#63、R-9）。手順は調整値の CSV と同じ。

**企画が称号を変えるとき**
1. 称号CSV タブ（または、もとの新称号案タブ・称号タブ）を書き換える
2. 称号CSV タブを開き、ファイル → ダウンロード → カンマ区切り形式（.csv、現在のシート）でダウンロードする
3. ダウンロードしたファイルで `src/titles.csv` を上書きする（ファイル名は `titles.csv` にする）
4. `npm run dev` 中ならそのまま反映される。公開版はビルドし直して反映する

**タブのしくみ**
- 1行目は見出し（`type,key,text,image`）。`type=word` は称号をつなげる言葉（20行。text が空欄なら言葉なし）、`type=comment` はひとこと（39行。key は判定キー）
- key を消したり、ひとことを空にしたりすると、ゲームは起動時にエラーを出す。key の名前は変えない
- `image`（完成イメージの説明）は今は読み込むだけで使わない（#55）

## Track の使い分け

- `Spec` — シートや game-plan.md の仕様を実装する作業
- `Tech` — 基盤、描画、テスト、リファクタリングなど技術面の作業
- `Release` — 公開・配信の作業
